KattuOna के लिए अपना AI सर्वर खुद चलाएँ

उन लोगों के लिए जो AI कोच के लिए किसी और के सर्वर पर निर्भर नहीं रहना चाहते।

KattuOna की AI सुविधाएँ (कोच चैट, खाना/व्यायाम लुकअप, भोजन के विचार, रेडीनेस चेक, प्रोग्राम बिल्डर) ऐसे किसी भी सर्वर से बात कर सकती हैं जो वही सरल प्रोटोकॉल बोलता हो — सिर्फ़ वह सर्वर नहीं जो ऐप में बिल्ट-इन है। यह पेज उन लोगों के लिए है जो यह सर्वर खुद चलाना चाहते हैं: किसी बेकार पड़े कंप्यूटर पर, एक होम सर्वर पर, एक छोटे VPS पर, जो भी आपके पास हो। फिर आपके सवाल और आपका फ़िटनेस डेटा सिर्फ़ उस मशीन तक जाते हैं जिसे आप नियंत्रित करते हैं, जो एक मुफ़्त लोकल AI मॉडल चलाती है (कोई सब्सक्रिप्शन नहीं, बीच में कोई कंपनी नहीं)।

आपको कोड आना ज़रूरी नहीं है। आपको एक ऐसा कंप्यूटर चाहिए जो चलता रह सके (या जब आप AI इस्तेमाल करना चाहें तब चालू किया जा सके), और एक AI कोडिंग असिस्टेंट — जैसे Claude Code — जो आपके लिए उस पर कमांड चला सके। नीचे दिया गया प्रॉम्प्ट उस असिस्टेंट को ठीक-ठीक बताता है कि क्या बनाना है।

1. आखिर में आपके पास क्या होगा

  • आपके कंप्यूटर पर चलने वाला एक छोटा, मुफ़्त लोकल AI मॉडल (Ollama के ज़रिए), जिससे किसी सवाल का जवाब देने के लिए आपके नेटवर्क से कुछ भी बाहर नहीं जाता।
  • इसके सामने एक छोटा गेटवे प्रोग्राम जिस तक KattuOna पहुँच सकता है, जो जवाब देने से पहले हर व्यक्ति की अपनी एक्सेस key जाँचता है।
  • इसे इस्तेमाल करने वाले हर व्यक्ति (आप, आपका पार्टनर, परिवार का हर सदस्य) के लिए एक-एक एक्सेस key — हर key सिर्फ़ एक नाम और एक रैंडम स्ट्रिंग है, बनाना या मिटाना आसान।
  • बाहर होने पर इसे अपने होम नेटवर्क के बाहर से पहुँचने का एक तरीका, अगर आप चाहें (Tailscale जैसा टूल सबसे आसान तरीका है — यह आपके होम कंप्यूटर को एक निजी अड्रेस देता है जिसे केवल आपके अपने डिवाइस पहुँच सकते हैं, पब्लिक इंटरनेट पर कोई पोर्ट खोले बिना)।

2. आपको क्या चाहिए होगा

  • एक कंप्यूटर जिसे आप चलता छोड़ सकें (एक छोटे मॉडल के लिए एक पुराना लैपटॉप भी काम करता है)। Linux, macOS या Windows (WSL के साथ) — सभी काम करते हैं।
  • वहाँ इंस्टॉल किया हुआ एक AI कोडिंग असिस्टेंट जो आपकी ओर से शेल कमांड चला सके — Claude Code एक सीधा विकल्प है, लेकिन वही क्षमता रखने वाला कोई भी असिस्टेंट काम करेगा।
  • लगभग 20–30 मिनट।

3. प्रॉम्प्ट

जो कंप्यूटर सर्वर चलाएगा उस पर एक टर्मिनल खोलें, अपने AI कोडिंग असिस्टेंट को एक खाली फ़ोल्डर में शुरू करें, और नीचे दिया पूरा बॉक्स अपने पहले मैसेज के रूप में पेस्ट करें। यह ठीक उस छोटी HTTP सेवा का वर्णन करता है जिसकी KattuOna को ज़रूरत है, ताकि असिस्टेंट इसे बना सके, टेस्ट कर सके, और ऑटोमैटिक रूप से शुरू होने के लिए सेट कर सके।

इसे अपने लोकल AI असिस्टेंट में पेस्ट करें 
I want to set up a small self-hosted AI server on this computer, for a fitness app called KattuOna to
talk to. Please do all of the following, explaining each step as you go, and actually run the
commands yourself rather than just telling me what to run:

1. Install Ollama (https://ollama.com) if it isn't already installed, and pull a small, fast
   instruction-tuned model suitable for CPU use (something in the 1-4B parameter range, such as
   llama3.2:3b-instruct-q4_K_M or a similarly sized alternative you judge to be a good fit for this
   machine's hardware). Confirm Ollama answers a test prompt on localhost:11434 before moving on.

2. Write a small HTTP gateway program (Python standard library only, no extra dependencies beyond
   what's already installed) that:
   - Listens on a local port of your choice (pick one not already in use, e.g. 8766, and tell me
     which).
   - Exposes POST /chat/completions, accepting a JSON body shaped like an OpenAI-style chat
     completion request: {"model": "...", "messages": [{"role": "...", "content": "..."}], ...}.
     Forward the messages to the local Ollama model and return a response in the same
     OpenAI-compatible shape: {"choices": [{"message": {"role": "assistant", "content": "..."}}]}.
   - Requires an `Authorization: Bearer ` header on every request. Keep a plain text file of
     valid keys, one per line, formatted as "name key" (e.g. "alex 7f3a9c2b1e..."), stored
     somewhere only this machine's admin can read (not world-readable). Reject requests with a
     missing or wrong key with HTTP 401, and don't log the key itself anywhere.
   - Caps request body size at a sane limit (e.g. 50KB) and returns 413 if exceeded.
   - Logs only minimal metadata per request (which person's key was used, timestamp, how long it
     took) -- never the message content, since this may include personal health/fitness details.
   - Add a small command-line helper (or a few short shell scripts) to add a new key for a person
     ("add-key NAME" -- generates a random key, appends "NAME key" to the keys file, prints the new
     key once so I can copy it), to remove one ("revoke NAME" -- deletes that person's line), and to
     list current names without printing their keys ("list-keys").

3. Set this gateway up as a service that starts automatically when the computer boots/restarts
   (systemd on Linux, launchd on macOS, or Task Scheduler / NSSM on Windows -- whichever fits this
   machine), and start it now.

4. Test it end-to-end: create one key for me, send a real chat request with it using curl and
   confirm a sensible model reply comes back, send a request with a wrong key and confirm I get
   401, and send an oversized request and confirm I get 413.

5. Tell me, in plain terms: the port number it's listening on, exactly how to run add-key / revoke /
   list-keys afterwards, and where the keys file lives. If I want to reach this server from outside
   my home network, suggest installing Tailscale (https://tailscale.com) and tell me the address
   KattuOna should use once that's set up -- don't open any ports directly on my router.

Please actually install, write, test and start all of this yourself rather than just giving me
instructions to run manually, and show me the real output of each test so I can see it worked.

अपनी ज़रूरत के हिसाब से इसमें बदलाव करें (अगर आपका कंप्यूटर धीमा या तेज़ है तो अलग मॉडल साइज़, अलग पोर्ट, वगैरह) इसे पेस्ट करने से पहले। आपका असिस्टेंट आपकी ख़ास मशीन के बारे में एक-दो फ़ॉलो-अप सवाल पूछ सकता है — यह सामान्य है, उनके जवाब दें और इसे आगे जारी रखने दें।

4. KattuOna को इसकी ओर इंगित करना

जब आपका असिस्टेंट अड्रेस और पोर्ट बता दे, तो KattuOna → Settings → AI इंजन → दूसरा सर्वर खोलें, और दर्ज करें:

  • अड्रेस — उदाहरण के लिए, अगर आप Tailscale इस्तेमाल कर रहे हैं तो http://100.x.x.x:8766, या अगर आप इसे सिर्फ़ घर पर इस्तेमाल कर रहे हैं तो आपके कंप्यूटर का लोकल अड्रेस और पोर्ट।
  • Key — वह key जो आपके असिस्टेंट ने आपके लिए (या जिस भी परिवार के सदस्य का फ़ोन सेट किया जा रहा है, उसके लिए) बनाई थी।

उसी स्क्रीन से इसे छोड़ने से पहले कनेक्शन टेस्ट करें।

5. लोगों को जोड़ना या हटाना

आपका सर्वर इस्तेमाल करने वाले हर व्यक्ति की अपनी key होनी चाहिए, ताकि आप अपने लॉग में उन्हें अलग-अलग पहचान सकें और बाद में किसी एक व्यक्ति की एक्सेस को बाकी किसी को प्रभावित किए बिना हटा सकें।

किसी को जोड़ें

सर्वर चलाने वाले कंप्यूटर पर (या SSH के ज़रिए), आपके असिस्टेंट द्वारा सेट किया गया हेल्पर चलाएँ, उदाहरण के लिए:

add-key NAME

यह एक बार एक नई key दिखाता है। इसे उस व्यक्ति के KattuOna ऐप में Settings → AI इंजन → दूसरा सर्वर में डालें।

किसी को हटाएँ

revoke NAME

उनकी key तुरंत काम करना बंद कर देती है। जब तक कोई नई key दर्ज नहीं की जाती, उनके KattuOna ऐप में एक कनेक्शन एरर दिखाई देगा।

देखें कि अभी किसकी एक्सेस है

list-keys

यह सिर्फ़ नाम दिखाता है, कभी keys नहीं, ताकि आप किसी की key को उजागर किए बिना यह पुष्टि कर सकें कि कौन सेट है।

ध्यान रखें: यह आपका अपना सर्वर है, इसलिए उस कंप्यूटर को ठीक-ठाक सुरक्षित रखना और उसकी keys को निजी रखना आपकी ज़िम्मेदारी है। अगर आपको कभी शक हो कि कोई key लीक हो गई है, तो उसे रिवोक करें और एक नई जारी करें। KattuOna का डेवलपर आपके द्वारा खुद चलाए जा रहे सर्वर पर कुछ भी नहीं देख या एक्सेस नहीं कर सकता।
