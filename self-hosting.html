Run your own AI server for KattuOna

For people who'd rather not rely on anyone else's server for the AI coach.

KattuOna's AI features (coach chat, food/exercise lookups, meal ideas, readiness check, program builder) can talk to any server that speaks the same simple protocol — not just the one built into the app. This page is for anyone who wants to run that server themselves: on a spare computer, a home server, a small VPS, whatever you have. Your questions and your fitness data then go only to a machine you control, running a free local AI model (no subscription, no company in the middle).

You don't need to know how to code. You do need a computer that can stay on (or be turned on when you want to use the AI), and an AI coding assistant — such as Claude Code — that can run commands on it for you. The prompt below tells that assistant exactly what to build.

1. What you'll end up with

  • A small, free local AI model running on your computer (via Ollama), so nothing leaves your network to answer a question.
  • A small gateway program in front of it that KattuOna can reach, which checks a per-person access key before answering.
  • One access key per person who'll use it (you, your partner, each family member) — each key is just a name and a random string, easy to create or delete.
  • A way to reach it from outside your home network when you're out, if you want that (a tool like Tailscale is the simplest way — it gives your home computer a private address only your own devices can reach, with no ports opened to the public internet).

2. What you'll need

  • A computer you can leave running (even an old laptop works for a small model). Linux, macOS or Windows (with WSL) all work.
  • An AI coding assistant installed there that can run shell commands on your behalf — Claude Code is a straightforward option, but any assistant with the same ability will do.
  • About 20–30 minutes.

3. The prompt

Open a terminal on the computer that will run the server, start your AI coding assistant in an empty folder, and paste the whole box below as your first message. It describes the exact small HTTP service KattuOna expects, so the assistant can build it, test it, and set it up to start automatically.

Paste this into your local AI assistant 
I want to set up a small self-hosted AI server on this computer, for a fitness app called KattuOna to
talk to. Please do all of the following, explaining each step as you go, and actually run the
commands yourself rather than just telling me what to run:

1. Install Ollama (https://ollama.com) if it isn't already installed, and pull a small, fast
   instruction-tuned model suitable for CPU use (something in the 1-4B parameter range, such as
   llama3.2:3b-instruct-q4_K_M or a similarly sized alternative you judge to be a good fit for this
   machine's hardware). Confirm Ollama answers a test prompt on localhost:11434 before moving on.

2. Write a small HTTP gateway program (Python standard library only, no extra dependencies beyond
   what's already installed) that:
   - Listens on a local port of your choice (pick one not already in use, e.g. 8766, and tell me
     which).
   - Exposes POST /chat/completions, accepting a JSON body shaped like an OpenAI-style chat
     completion request: {"model": "...", "messages": [{"role": "...", "content": "..."}], ...}.
     Forward the messages to the local Ollama model and return a response in the same
     OpenAI-compatible shape: {"choices": [{"message": {"role": "assistant", "content": "..."}}]}.
   - Requires an `Authorization: Bearer ` header on every request. Keep a plain text file of
     valid keys, one per line, formatted as "name key" (e.g. "alex 7f3a9c2b1e..."), stored
     somewhere only this machine's admin can read (not world-readable). Reject requests with a
     missing or wrong key with HTTP 401, and don't log the key itself anywhere.
   - Caps request body size at a sane limit (e.g. 50KB) and returns 413 if exceeded.
   - Logs only minimal metadata per request (which person's key was used, timestamp, how long it
     took) -- never the message content, since this may include personal health/fitness details.
   - Add a small command-line helper (or a few short shell scripts) to add a new key for a person
     ("add-key NAME" -- generates a random key, appends "NAME key" to the keys file, prints the new
     key once so I can copy it), to remove one ("revoke NAME" -- deletes that person's line), and to
     list current names without printing their keys ("list-keys").

3. Set this gateway up as a service that starts automatically when the computer boots/restarts
   (systemd on Linux, launchd on macOS, or Task Scheduler / NSSM on Windows -- whichever fits this
   machine), and start it now.

4. Test it end-to-end: create one key for me, send a real chat request with it using curl and
   confirm a sensible model reply comes back, send a request with a wrong key and confirm I get
   401, and send an oversized request and confirm I get 413.

5. Tell me, in plain terms: the port number it's listening on, exactly how to run add-key / revoke /
   list-keys afterwards, and where the keys file lives. If I want to reach this server from outside
   my home network, suggest installing Tailscale (https://tailscale.com) and tell me the address
   KattuOna should use once that's set up -- don't open any ports directly on my router.

Please actually install, write, test and start all of this yourself rather than just giving me
instructions to run manually, and show me the real output of each test so I can see it worked.

Swap in whatever details you want changed (a different model size if your computer is slower or faster, a different port, and so on) before pasting it. Your assistant may ask a couple of follow-up questions about your specific machine — that's normal, answer them and let it continue.

4. Pointing KattuOna at it

Once your assistant reports back the address and port, open KattuOna → Settings → AI engine → Another server, and enter:

  • Address — e.g. http://100.x.x.x:8766 if you're using Tailscale, or your computer's local address plus port if you're only using it at home.
  • Key — the key your assistant generated for you (or for whichever family member is setting up their phone).

Test the connection from that same screen before leaving it.

5. Adding or removing people

Each person who'll use your server should have their own key, so you can tell them apart in your logs and remove just one person's access later without affecting anyone else.

Add someone

On the computer running the server (or over SSH), run the helper your assistant set up, for example:

add-key NAME

This prints a new key once. Copy it into that person's KattuOna app under Settings → AI engine → Another server.

Remove someone

revoke NAME

Their key stops working immediately. Their KattuOna app will show a connection error until a new key is entered.

See who currently has access

list-keys

This lists names only, never the keys themselves, so you can confirm who's set up without exposing anyone's key.

Keep in mind: this is your own server, so you're responsible for keeping that computer reasonably secure and its keys private. If you ever suspect a key has leaked, revoke it and issue a new one. KattuOna's developer cannot see or access anything on a server you run yourself.
